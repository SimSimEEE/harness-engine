# 프리플라이트 게이트 — 설계

커밋과 PR 앞에 놓인 품질 검사 하네스. 변경을 결정론적으로 분류해 필요한 검사만 병렬로
돌리고, 결과가 아니라 **절차가 밟혔는지**를 검증한 뒤, 훅이 커밋을 막는다.

리뷰를 받으려고 쓴 문서다. 잘한 것보다 **한계와 물어보고 싶은 것**에 무게를 뒀다.

---

## 1. 전제

- **실질 사용자가 한 명이다.** 팀 강제나 거버넌스가 목적이 아니다. CI·브랜치 보호는
  의도적으로 넣지 않았다 — 같은 검사를 서버에서 한 번 더 하는 것뿐이고, 조직이 GitHub
  Free 라 private 레포에 브랜치 보호를 걸 수도 없다.
- **검사 주체가 LLM 이다.** 따라서 "검사가 통과했다"는 보고를 그대로 믿을 수 없다.
  결과 검증만으로는 부족하고 **절차 검증**이 필요하다.
- **속도가 채택을 좌우한다.** 느리면 우회한다. 관측 로그에 우회 3건이 있다.

### 설계 원칙 셋

1. **선택은 코드가 한다.** 어떤 검사를 돌릴지 LLM 이 고르지 않는다.
2. **기계로 표현되는 판정은 기계로 내린다.** 정규식으로 쓸 수 있는 것을 LLM 이 판단하면
   느리고, 흔들리고, 오탐이 난다.
3. **규칙은 전수 실측 뒤에만 넣는다.** 문서에 있다는 이유로 규칙이 되지 않는다.

## 2. 실행 경로

```
classify.sh ──▶ preflight.js ──▶ 집계 ──▶ receipt.sh ──▶ PreToolUse 훅
 결정론          LLM · 병렬       결정론     결정론          결정론
 lane 선택       lane 실행        판정 산출  절차 검증       커밋 직전 재검증
```

**LLM 은 가운데 한 칸에만 있다.** 무엇을 검사할지도, 결과를 어떻게 합칠지도, 통과 여부도
코드가 정한다. lane 판정어 → verdict 매핑은 `preflight.js` 한 곳에만 있고 에이전트 정의에
복사하지 않는다.

### 엔진과 카테고리 규칙

결정론 분류는 두 층이다. **엔진**(`classify.sh`)은 모든 레포에 같은 규칙 — 파일 확장자·경로로 lane 고르기,
항상 도는 `secret-scanner`, 순차 체인, 계획·QA 결속 — 을 갖고 카테고리 이름을 모른다. **카테고리 규칙**
(`skills/preflight/categories/<이름>/rules.py`, 그리고 오버레이의 `categories/<이름>/rules.py`)은 레포 성격에 따른 판정을 갖는다:

```
categories/categories.json        선언 — 있어야 할 카테고리 목록 (디렉터리와 어긋나면 분류하지 않는다) · fallback
categories/shell-tool/            스냅숏에 meta-test.sh + preflight-gate.sh: 자체 회귀 스위트 (이 엔진 레포)
categories/generic/               기본(fallback) — 다른 카테고리에 신호가 없을 때. 규칙 없음
<오버레이>/categories/<이름>/      조직 전용 카테고리 — 예: 공용 코어 패키지 의존 TS 백엔드(관례 판정, QA 엔드포인트, dev 배포 안내,
                                  vault 등록 조회·vault-sync, 의존 줄), 지식 vault(VAULT_RULES.md: vault 문서 → vault-linter)
```

오버레이 루트는 설치본 `config.json` 의 `overlayDir`(또는 `PF_OVERLAY_DIR`)다. 엔진 체크아웃은 공개이고 조직 규칙은
오버레이 레포에 둔다 — 루트 사이 이름이 겹치면 분류하지 않는다(exit 3).

`classify.sh` 가 선언을 읽어 각 카테고리의 `match()` 로 소속을 정한다. 대상 레포는 하나에만 속하고, 둘 이상에
걸리면 분류하지 않고 끝난다(exit 3). 어느 것에도 속하지 않으면 엔진 규칙만 걸린다. 카테고리 규칙도 Python
코드라 같은 입력이면 같은 판정이다 — 산문을 LLM 이 해석하지 않는다.

**조회 명령** `category.sh <repo>` 는 같은 판정 코드(`classify.sh` 의 category 모드)로 카테고리·근거 신호·
그 카테고리의 절차 요구(`categories/<이름>/procedures.json`)를 낸다. 게이트 경로 밖에 있고 아무것도 쓰지 않는다.

**회귀 스위트**도 같은 경계로 나뉜다. 진입점 `skills/preflight/meta-test.sh` 가 한 셸에서 `meta-test/lib.sh`(공용
헬퍼·픽스처) → `meta-test/engine.sh` → `categories/<이름>/meta-test.sh`(선언 순, 없으면 건너뜀) →
오버레이 카테고리 파일 → 훅·프로필·오버레이 절 → 오버레이의 `meta-test.d/*.sh` 순으로 source 한다. 파일들은 상태를
이어 쓰므로 카테고리 파일만 따로 돌리지 않는다. 카테고리 규칙 훅을 거쳐야 드러나는 단언은 그 규칙을 가진 카테고리의
스위트에 둔다 — 엔진 스위트의 공용 픽스처는 기본 카테고리다.

### 순서

```
코드 작성 → dev 배포 → 커밋 게이트 --qa → 보고·검토·수정 → 커밋 → PR 게이트 → PR 생성
```

QA 를 커밋 게이트에 두는 이유는 결과가 `indexTree` 로 **커밋될 내용에 묶이기** 때문이다(QA 기록의 키).
커밋 게이트의 순서는 **고친다 → `git add` → classify → lane → record → commit** 이고, 분류 뒤 인덱스가 바뀌면
재분류한다(`record` 가 `index-changed` 로 거부한다). 워킹트리에만 있는 차이(다른 세션의 미스테이징 수정·
미추적 파일, 부분 스테이징)는 커밋되지 않으므로 기록을 막지 않고 `record` 가 경로 목록만 보여 준다.
`--qa` 커밋 게이트만 예외다 — dev 배포는 워킹트리를 빌드하므로 **커밋될 경로**의 워킹트리가 인덱스와 달라지면
`qa-worktree-differs` 로 거부한다(커밋되지 않는 경로는 요구하지 않는다).
PR 게이트에서 돌리면 이미 커밋된 뒤라 그 사이 변경을 잡지 못한다.

## 3. 신뢰 경계 — 결속 값

"검사한 것"과 "커밋될 것"이 갈리는 지점이 이 설계의 핵심 위험이다.

| 값 | 무엇을 고정하는가 | 왜 |
|---|---|---|
| `contentDigest` | 검사 대상(스냅숏)의 내용 — 커밋 모드는 **커밋될 인덱스**, PR 모드는 base..HEAD | 워킹트리만 바꾸는 조작(미추적·미스테이징)에는 안 움직이고, 스테이징 내용이 바뀌면 움직인다 (#8). 분류 식별자·라운드 집계용이고 `record` 는 대조하지 않는다 — 대상 결속은 `indexTree`(커밋)·`head`(PR)가 맡는다 |
| `indexTree` | 실제로 **커밋될 트리** | 분류가 기록해 두고 `record` 가 다시 대조한다(`index-changed`). 훅도 커밋 직전에 대조한다. 커밋될 내용의 결속은 이것 하나다 — 분류 뒤 워킹트리 변화는 결속 대상이 아니다(lane 은 이 트리를 푼 스냅숏을 읽는다) |
| `seenTree` (영수증) | lane 이 **본 상태** — 분류의 스냅숏 트리 | 커밋 모드는 `indexTree` 와 같다. 워킹트리에서 계산한 값은 남기지 않는다 |
| `qa` | 이 분류가 `--qa` 라운드인가 | `record` 가 이 값으로 `--qa` 예외(커밋될 경로의 워킹트리 = 인덱스)를 건다. record 인자로 끌 수 없고, 지우거나 qa lane 과 어긋나면 `classify-schema-old` |
| `snapshot` | lane 이 읽을 트리(커밋 모드 인덱스, PR 모드 HEAD)와 체크아웃 필요 여부 | 워크플로가 `snapshot.sh` 로 그 트리를 격리 체크아웃으로 풀고 트리 id 를 대조한 뒤 경로만 lane 에 준다. 끝나면 지운다 |
| `classificationId` | 이 검사가 **어떤 분류**에 대한 것인가 | 분류 없이 기록하거나 낡은 분류로 기록하는 것을 거부 |

**실제로 발생한 TOCTOU**: 훅은 명령이 실행되기 **전**에 인덱스를 검증하므로
`git add x && git commit` 은 검사되지 않은 내용을 통과시킨다(재현 확인). 지금은 이 형태와
`git commit -a/-am` 을 거부한다.

## 4. 절차 검증

결과가 아니라 절차를 본다. `record` 가 거부하는 조건:

| 사유 코드 | 무엇을 막는가 |
|---|---|
| `incomplete-lanes` | 선택된 lane 중 결과가 없는 것 — 미실행은 통과가 아니다 |
| `no-lane-evidence` | 전사에 도구 실행이 하나도 없다 — 보고는 있으나 검사는 없었다 |
| `sequence-violated` | 순차 lane 의 순서가 어긋났다 — 뒤 lane 이 앞 결과 없이 판정했다 |
| `concealed-promotion` | 전사 verdict 는 WARNING 인데 `waived` 없이 PASS 로 기록 |
| `index-changed` | 분류 이후 커밋될 인덱스가 바뀌었다(분류 뒤 `git add`·다른 세션의 스테이징) |
| `qa-worktree-differs` | `--qa` 커밋 게이트인데 커밋될 경로의 워킹트리가 인덱스와 다르다 — QA 가 본 배포본과 커밋될 내용이 갈렸다 |
| `no-classification` | 분류기를 안 돌렸다 |
| `no-gate-run` | 워크플로를 안 돌렸다 — lane 결과가 전무. 분류는 무엇을 검사할지 정할 뿐이다 |
| `qa-not-executed` | QA 가 통과로 보고됐는데 전사에 URL 이 실린 실행 명령이 0건 — 읽기만 했다 |
| `vault-unregistered` | PR 게이트인데 추적 노트가 없다 |
| `plan-changed` | PR 게이트인데 결속된 계획의 claim 이 승인 뒤 바뀌었다 — 승인된 약속과 추적 기준이 다르다 |
| `lane-status` | FAIL 이거나 승인 없는 WARNING |

vault 상태 중 **통과하는 것**은 `REGISTERED`(추적 중) · `SELF`(vault 자신) · `EXEMPT`(추적하지 않기로 결정 — `config.json` 의 `vaultExempt` 또는 `VAULT_EXEMPT`) · `UNKNOWN`(등록 대상을 특정할 수 없음) 넷이다. 그 외는 거부한다 — **거부 목록이 아니라 통과 목록**이라
새 상태가 조용히 통과하지 않는다.

### vault 대기 목록 — 드리프트는 막지 않고 모은다

등록은 랜딩의 전제로 남지만(위 `vault-unregistered`), **노트 드리프트는 PR 을 막지 않는다.** PR 시점에는
마일스톤 완료가 아직 참이 아니어서, 그때 갱신을 강제하면 기능 하나에 브랜치·머지·배포마다 vault 커밋이 생겼다.

- `vault-sync` 는 드리프트를 종류(이번 변경 / 원래 있던 / 확인 필요)를 갈라 구조(`drifts[]`)로 내고 verdict 는 PASS 다.
  쓰기는 여전히 하지 않는다(`writes: false`).
- `record pr` 이 그 출력을 **전사에서** 읽어 레포별 대기 목록(`~/.claude/vault-queue/`)에 적재한다. 적재는 영수증을 쓴
  **뒤**에 하므로 다른 lane 의 판정·거부 사유를 바꾸지 못하고, 실패는 기록을 거부하지 않는 대신 보고·관측 로그에 남는다.
- 경고(머지 수 근사 3건 또는 7일)와 머지 보고의 `vault 미반영 N건` 은 네트워크 없이 대기 목록과 영수증만 읽는다.
- 반영은 `vault-batch-sync` 스킬이 한다. **판정은 스크립트(그 카테고리의 `vault-queue.sh` — vault-sync 와 같은 카테고리 규칙)가 하고 에이전트는 문안·승인 대화만 한다** —
  같은 원칙(기계로 표현되는 판정은 기계로)이다. 대기 항목은 후보일 뿐이라 반영 시점에 원격 상태로 다시 대조하고,
  커밋은 `origin/master` 위에 임시 인덱스로 조립해 vault 워킹트리·인덱스를 건드리지 않는다. 허용 목록 밖 경로·필드,
  게이트 어휘, 대기 목록 식별자가 diff 에 섞이면 커밋하지 않는다. 항목은 반영 vault PR 이 **머지된 뒤에만** 빠진다.

### 증거는 self-report 로 받지 않는다

lane 에게 `evidence` 필드를 채우게 하면 **그것도 LLM 이 쓴 주장**이다. 대신 **에이전트
전사**(`agent-*.jsonl`)를 본다 — 코드가 관찰한 실행 사실이다.

최소 증거 = **실행 명령 + 실행 시각 + 종료 상태 + 대상**. 넷 다 전사에서 관찰된다
(`input.command`, `timestamp`, `tool_result.is_error`, 명령 문자열). 출력 내용이 옳은지는
보지 않는다 — 별도 artifact 가 필요하고 최소 증거의 범위를 넘는다.

lane 식별은 **구조화 출력의 `lane` 값으로만** 한다. 프롬프트 본문에도 lane 이름이 들어 있어
본문 grep 으로 매칭하면 남의 전사를 자기 것으로 오인한다.

**전사를 넘기지 않아도 기록은 된다.** 실효를 관측하기 전에 막는 것은 과하다 — 강제해서
우회를 낳은 전례가 있다(§ 6).

## 5. 판정을 코드로 내리기

LLM 판단에서 결정론으로 내린 검사 셋. 셋 다 **전수 실측으로 규칙을 검증한 뒤에만** 넣었다.

| 검사기 | 무엇을 | 실측 | 비용 |
|---|---|---|---|
| `convention-check.sh` (TS 백엔드 카테고리 — 오버레이) | 헤더 `@author`/`@date`/`@copyright`, `const NS` 형식, 컨트롤러 default export | 404개 파일 · 위반 7 | 0.07초 |
| `pr-format-check.sh` | 브랜치명, base, 커밋 형식·언어, PR 제목 | PR 162건 · 커밋 653건 | <1초 |
| `qa-endpoint.sh` (TS 백엔드 카테고리 — 오버레이) | 레포 → dev 엔드포인트 (배포된 API Gateway, 24h 캐시) | 검증셋 5/5 | 캐시 히트 |

### blocking 은 위반율만으로 정하지 않는다

규칙을 **넣는 것**과 **막는 것**은 다른 결정이다. 넷을 함께 본다:

| 축 | 묻는 것 |
|---|---|
| 위반율 | 지금 작업 흐름을 얼마나 막는가 — **강제 비용**의 축이지 정당성의 축이 아니다 |
| 영향도 | 위반이 실제 사고·품질 저하로 이어지는 크기 |
| 복구 비용 | 나중에 고치기 얼마나 어려운가 |
| 자동 수정 가능성 | 게이트가 즉시 해결해줄 수 있는가 |

위반율만 쓰면 **"이미 다들 지키는 규칙만 강제한다"** 는 편향이 생긴다. 실제로 이 게이트는
이미 4축을 쓰고 있었다 — `secret-scanner` 는 위반율과 무관하게 항상 돈다(영향도가 재앙적).
명문화된 규칙이 실무보다 좁았던 것이다.

### 수치를 쓸 때

**수치 주장은 재현 가능한 명령의 출력이어야 한다. 명령을 적을 수 없으면 수치를 쓰지 마라.**
일회용 스크립트로 센 값은 수치가 아니라 **관찰**로 적는다. 이 규칙이 없어서 정본 문서의
규칙 하나를 잘못 제거한 적이 있다(§ 6).

## 6. 알려진 한계

### 게이트는 사실 주장을 검사하지 않는다

가장 큰 구조적 한계다. 정본 문서의 규칙 하나를 "404개 중 342개(84%)가 미준수"라며 제거하는
변경이 **커밋 게이트 통과 → PR 게이트 통과 → 머지**까지 갔다. 측정에 쓴 정규식이 표기 변형
하나를 놓쳐 나온 정반대 결론이었고(실제 400/404 준수), 잡은 것은 사람이었다.

게이트는 형식·회귀·규약을 본다. 사실 주장은 보지 않았다. 그리고 작업의 상당 부분이 사실
주장이다.

지금은 세 층이 있고 **셋 다 판정에 개입하지 않는 참고층**이다(4축 실측 전 — `skills/preflight/DECISIONS.md`
2026-11-06·2026-11-12):

- ① 추출(`claim-extract.sh`) — 바뀐 문서·커밋 메시지·PR 본문에서 비율·백분율·건수·부재 주장과 붙은 재현 명령을 뽑는다.
- ② 출처 대조(`claim-verify.sh`) — 붙은 명령을 샌드박스 안에서 다시 돌려 출력에 주장 숫자가 있는지 본다. 출처가 주장을
  떠받치는지만 보므로, 명령 자체가 틀리면(위 사건의 정규식) 다시 돌려도 같은 숫자라 못 잡는다.
- ③ 재측정(`claim-remeasure.sh` + `claim-remeasurer` 에이전트) — 규칙 줄을 지우거나 바꾸면서 비율·백분율·부재를 주장한
  변경만, 원래 명령과 숫자를 가린 채 다른 방법으로 다시 잰다. 고르기·가리기·등록 레포 스냅숏·대조는 결정론 코드이고 LLM 은
  측정과 자리 해석만 한다. 호출은 게이트당 1회, 재측정하는 주장 수의 상한은 K=5 다.

남는 한계: ③의 측정은 LLM 이 하므로 흔들리고(픽스처 실측은 `DECISIONS.md` "③ 실측" — 여러 레포에 걸친 코퍼스에서
귀속이 갈리고 일부만 등록된 코퍼스를 남은 레포로 대신 세는 일이 나왔다), lane 이 스냅숏에서 원래 주장을 읽으면 앵커링 차단이 뚫리며,
독립성은 lane 이 보고한 명령으로만 확인한다. 레포 밖 코퍼스는 등록된 로컬 레포의 이미 fetch 된 origin 트리만 세므로
미등록 레포를 세는 주장은 측정 불가로 남고 원격보다 낡을 수 있다. 규칙 줄 판별식은 어미로 고르므로 서술도 잡는다.

### 산문 절차는 세션에 고정된다

스크립트·에이전트 정의·훅은 매 실행마다 디스크에서 읽히므로 즉시 반영된다. 그러나
`SKILL.md` 는 세션이 스킬을 처음 호출할 때 컨텍스트로 들어가고 갱신되지 않는다. 오래 돌던
세션은 **옛 절차를 진실로 알고** 있다 — 코드와 산문이 갈린다. 완화책은 판정을 산문에서
코드로 계속 내리는 것뿐이다.

### 회귀 테스트 일부는 문구 존재만 본다

195개 중 대부분은 실제로 검사기를 실행하고 결과를 본다. 나머지는 에이전트 정의에 특정
문장이 있는지만 확인한다 — **주입했다는 사실을 고정한 것이지 효과를 고정한 것이 아니다.**
문구를 다듬으면 실패하고, 에이전트가 무시하면 통과한다.

### 검증되지 않는 것들

- **배포본 동일성** — dev 에 떠 있는 빌드가 커밋될 내용과 같은지 확인할 방법이 없다.
  헬스 응답에 빌드 식별자가 없다.
- **`codeLogicChange`** — diff 라인이 전부 주석·공백인지로 보는 휴리스틱. 불확실하면
  도는 쪽으로 기운다.
- **공개 타입 표면** — 로컬 상대 import 폐포만 따라간다. `paths` alias 와 패키지 import 는
  따라가지 않는다.

### 도구를 믿어서 틀린다

관측 도구가 잘못 답해서 결론이 뒤집힌 사례가 하루에 다섯 번 나왔다 — 정규식이 표기 변형을
놓치고, 출력이 잘려 명령 뒷부분이 안 보이고, grep 어휘가 문서 어휘와 달라 "없다"로 읽고,
앵커 없는 정규식이 다른 필드를 잡고, `git grep --cached` 가 옵션 순서 오류로 죽은 것을 0건으로
읽었다. 넷은 결론 전에 한 번 더 봐서 걸렀고 **하나는 머지까지 갔다.**

### 메타테스트가 게이트보다 자주 틀린다

같은 날 테스트 하네스 버그가 네 번 나왔다 — `pipefail` 아래서 `검사기 | grep` 이 항상 실패,
로그를 대상 레포 안에 만들어 다이제스트가 바뀜, 픽스처에 필요한 전사 누락, 앞 케이스가 남긴
분류 잔존. 전부 "검사기가 틀렸다"로 읽힐 뻔했다. **실패를 보면 검사기보다 하네스를 먼저
의심한다.**

## 7. 리뷰 요청 지점

1. **절차 검증의 적정 층위** — 지금은 실행 사실과 순서까지 본다. 각 lane이 *무엇을* 봤는지는
   보지 않는다. LLM 이 검사 주체일 때 어디까지 검증해야 비용 대비 값어치가 있는가.
2. **사실 주장 검사** — § 6 의 첫 한계. 과한 형식화 없이 가능한 설계가 있는가. 지금은
   "수치는 재현 가능한 명령의 출력이어야 한다"는 규칙만 있고 강제는 없다.
3. **문구 존재 단언을 실행 기반으로** — 알려진 결함을 심은 fixture 에 lane 을 돌려 잡는지
   보는 방식을 생각 중이다. LLM lane 이라 flaky 할 텐데 회귀 게이트로 쓸 만한 형태가 되는가.
4. **단일 사용자 전제가 무너질 때** — 우회 정책이 먼저 깨질 것으로 본다. 지금은 우회자가 곧
   승인자다. 둘이 갈리면 기록만 남고 통제는 없다.
5. **자기 참조 비용** — `~/.claude` 가 이 레포로의 심링크라 **게이트를 고치면 그 수정이
   게이트가 검사할 내용이 된다.** 최초 커밋에 6라운드가 들었고 매 라운드가 직전 라운드
   수정에서 만든 결함을 찾았다. 결속이 제대로 걸린 증거이지만 종료 조건이 필요하다.
